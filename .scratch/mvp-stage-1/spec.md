本窗口是第 1 窗口“账户、上传与视频管理”，对应技术方案第 2 阶段。产品与技术文档中的最新范围决定优先：上传视频不设单文件字节上限，业务数据目录暂不设运行期 5 GiB 硬上限、容量准入水位和容量预留；媒体有效时长仍须大于 0 且不超过 20 分钟。取消容量限制意味着不能保证磁盘永不耗尽，普通文件写入失败仍须安全失败并留下可恢复的清理事实；Docker 新增占用 7 GiB 预算仍有效。

本窗口目标：

交付并验证一条可运行的后端闭环：两个账号分别注册、登录，使用原始请求体流式上传课程视频，鉴权查询与读取自己的视频，再删除未执行分析的视频并完成可重试的文件清理。

范围：

1. 在第 0 窗口成果上建立最小 FastAPI 后端、锁定且实际验证过的业务依赖、PostgreSQL 模型及 Alembic 迁移、可复现的本地运行配置和直接相关测试。正式业务数据仍放在 E:\VideoClip\data 下受控目录；业务数据库、端口、容器和测试数据与第 0 窗口探针隔离。只实现当前闭环所需的数据与模块接口，明确账号、视频、存储及媒体规则的写入归属，为后续任务生命周期留下清晰接入点。
2. 实现注册、登录、当前用户、退出和会话失效。密码使用 Argon2id，数据库只存随机会话令牌的哈希；Cookie 配置 HttpOnly、SameSite 与有效期，开发 HTTP / HTTPS 的 Secure 行为明确。状态变更接口检查 Origin 和 CSRF 令牌，并提供可供匿名注册/登录及已登录客户端获取令牌的方式；所有视频及媒体操作由服务端校验所属账号，对其他账号的资源统一返回不可见结果。限制会话、输入和诊断大小，密钥及会话令牌不得进入日志或 Git。
3. 实现与 XMLHttpRequest 原始请求体兼容的流式上传接口，不采用会先写入未受控临时目录的默认 multipart 路径。读取前持久化上传交接记录、写入者身份和受控 .part 路径；分块写入并计算实际字节数与内容摘要，原文件名仅作展示，路径由服务端生成。不得按 1 GiB、Content-Length、扩展名或 MIME 类型作容量拒绝；读取、ffprobe、数据库锁等待及清理设置有限总期限，并让正常 1 GiB 以上样本在该期限内可完成上传。断开、文件系统 I/O 失败或进程异常时保留可定位的清理意图。
4. 使用 ffprobe 校验有效视频流、音轨和有限时长（0 < 时长 ≤ 1200 秒）；依据第 0 窗口证据，仅接受已验证的 MP4 家族、单路 H.264 yuv420p 视频、单路 AAC 音频及容器/音视频轨零起点时间轴。偏移、无法证明映射正确或不受支持的媒体明确拒绝。可以提取已验证的媒体纯规则并保留第 0 窗口回归测试；不把探针整个流程复制成正式业务实现，也不自动转码。
5. 先持久化正式目标路径及交接意图，再改名并登记不可变源视频身份、字节数、内容摘要、时长和媒体信息；文件与数据库之间的失败窗口通过持久化记录补偿，重启后可安全继续处理。清理 .part 或目标文件前须证明原 API 写入者已停止，不能仅凭记录过期判断已退出；重复清理安全且不得删掉仍在使用的路径。
6. 实现视频列表、详情及鉴权内容读取，后者支持 HEAD、有效 Range 的 206 和无效 Range 的 416；未登录、其他账号及已删除视频均不能访问内容。实现未执行分析视频的删除：持久化删除标记和清理意图后立即阻止新内容读取，再回收文件；失败保留路径与错误供重试，未回收完成不报告删除完成。已经有任务或无法证明未执行的视频不得走此阶段的直接删除路径，其停止与失效协调留待后续分析窗口。
7. 保存运行命令、迁移/回滚边界、关键测试和真实样本验收结果至 .scratch/mvp-stage-1/validation.md；完成有意义的阶段后更新现有技术方案的进度、限制和下一步。维护本阶段所需的配置示例、忽略规则及本项目限定的启停步骤；保护第 0 窗口的探针、授权源视频、私密配置和其他 Docker 项目。

验收：

1. 新建隔离业务数据库并执行 Alembic 迁移后，能按文档命令启动 API。两个账号分别注册、登录、查询当前用户、退出；退出后旧会话失效。缺失/错误 Origin 或 CSRF、未登录及跨账号访问被拒绝；除登录所需的受保护 Set-Cookie 外，普通响应与日志不泄露绝对路径、密钥或会话令牌。使用真实 PostgreSQL 集成验证。
2. 使用原始请求体真实 HTTP 上传第 0 窗口的 1,116,803,236 字节授权视频，确认成功保存、实际字节数和摘要正确、重启后列表/详情仍可查，且不存在 1 GiB 或业务目录容量准入拒绝。自动化测试以小型 fixture 覆盖流式与边界行为，大文件真实验收运行一次并记录命令、耗时及结果；不反复复制大文件作为每个测试的前置条件。
3. 空文件、无音轨、零/无效时长、超过 20 分钟、不支持编码及带音轨偏移的媒体均明确拒绝；支持样本的媒体信息与时间轴证据持久化。ffprobe 挂起时总期限生效并回收子进程，失败不留下可访问的视频记录。
4. 模拟或实际验证上传断开、文件写入错误、改名前后进程退出及登记事务失败；重启后的上传交接和清理不会遗失路径、误删活跃写入或把半成品当成成功视频。普通 I/O 失败按错误处理，不能声称进行了容量准入或写满拒绝验证。
5. 本人带会话 Cookie 的视频内容请求支持 HEAD、206 Range 与 416；另一账号、退出后的会话及删除后的新请求均被拒绝。未执行视频删除后内容立刻不可访问，文件与记录最终清理；删除/清理重复执行安全，模拟清理失败时保持待处理状态和可重试路径，不提前宣布完成。
6. 运行直接相关单元及集成测试、全部适用后端测试、lint、类型检查、依赖检查、迁移与容器配置校验；如复用或修改第 0 窗口代码，还须运行其回归测试。记录真实执行命令和结果。构建/运行本项目业务环境后测量 Docker 新增镜像、缓存、可写层及日志占用，核对 7 GiB 预算并确认其他项目未被改动；第 0 窗口约 77,865 字节的探针增量不能替代本次业务环境测量。
