# 最终版第 2 窗口规格

## 目标与前置条件

本窗口在第 1 窗口提交 `84cd5bb` 的分片上传后端之上，接入真实浏览器的断点续传，并部署独立的临时上传周期回收链路。开始时核对当前分支为 `codex/mvp`、HEAD 为 `84cd5bb`；未切换或重置分支。Stage 2 使用既有私密配置和 E 盘数据目录，Stage 1 数据库仅用于隔离后端测试。

页面须以服务端 `confirmed_offset` 与会话状态作为上传事实源。用户刷新后重新选择原文件，浏览器重新计算完整 SHA-256 并校验已确认分片；只在相同内容时续传。摘要与各分片摘要使用锁定版本 `@noble/hashes@1.8.0` 增量计算，不把完整视频读入内存。浏览器只按当前账户在 `localStorage` 保存文件名、长度、完整摘要、幂等键、会话 ID 和创建时间，不保存文件内容或凭据。上传暂停保留会话，放弃调用既有 DELETE 接口。

## 范围

### 浏览器分片续传

- 默认上传组件改用第 1 窗口 `/uploads` 会话、状态、分片、完成与放弃接口；普通 `/videos` 上传接口保持兼容。
- 创建前持久化幂等元数据；创建响应丢失时复用相同幂等键。会话状态查询后才决定分片偏移，响应不确定时先读服务端确认位置。
- 通过 Web Worker 对 `Blob.slice()` 分片进行完整文件及分片摘要计算；XHR 提供当前请求进度与中止能力，UI 将摘要、传输、完成校验及服务端已确认字节分开显示。
- 账户 ID 分区隔离恢复信息。登出、会话过期或账户组件卸载时停止旧请求并释放当前 File 引用；不会为前一个账户自动续传。
- 暂态错误采用有限重试与短退避。损坏、偏移冲突、过期及失效状态保留恢复信息并给出稳定错误提示。完成响应不确定时查询状态并幂等重试，完成状态返回同一个视频。
- 202 放弃响应表示清理仍待完成，保留本地恢复信息；204 才清除。服务端已完成会话不能通过放弃删除视频。

### 临时上传周期回收

- 一个 Celery Beat 每 60 秒投递一次回收任务；Beat 的持久调度文件写到 `data/mvp-stage-2/app/maintenance-beat-schedule`。
- 新增只订阅 `maintenance` 队列、并发 1 的维护 Worker；周期业务只调用 `reclaim_expired_uploads`。维护扫描上限默认每轮 4 条、硬上限 8 条。
- 分析任务明确路由到 `analysis` 队列；现有分析 Worker 仍单并发并只订阅分析队列。
- Redis 单飞锁合并排队/运行中的重复周期触发，PostgreSQL advisory lock 防止并发扫描；失败记录保留持久化清理意图，后续周期重试。
- 回收尊重文件租约、完成交接与已登记视频；稳定租约标记文件保留。既有 24 小时有效期不因状态查询或重放分片延长。
- 维护服务复用后端镜像，Beat 与维护 Worker 分别限制内存/PID，JSON 日志各轮转 10 MiB × 2；Beat 和临时文件均落 E 盘项目数据目录。

## 非目标与约束

不在本窗口加入进程监督/可信停止证明、分析排队协调或补投、共享冷却、分析自动恢复、媒体与笔记分离删除或最终版执行时间线。增加 Beat 不代表分析自动恢复完成。保护现有视频、task、attempt、冻结快照、检查点和失败记录，不调用模型、不提交分析任务，不修改旧 v4 配置或秘密配置。Stage 0 中容器可写层处理中峰值、E 盘差额归因、账户计费及完整 20 分钟模型处理仍是独立未验证项。

## 验收

- 单元测试覆盖摘要、分片边界、幂等键、服务端偏移恢复、错误文件拒绝、账户隔离、暂停/放弃以及完成响应丢失。
- 使用既有授权长视频在 Chromium 中制造非零确认偏移中断，刷新后重新选原文件续传；同名同长度错误内容不得续传。核对分片请求、唯一视频登记和鉴权媒体读取。
- 通过真实 Beat、Redis 和维护 Worker 链路覆盖到期清理、活跃租约跳过、清理失败留存后重试、维护 Worker 重启及稳定租约标记保留；同时核对完成/放弃/回收竞态测试。
- 验证维护 Worker 只消费维护队列、分析 Worker 并发 1、分析队列与模型调用不变；记录迁移、Compose、完整后端及 Stage 0 回归、lint/类型/依赖检查、前端 lint/单测/构建和浏览器证据。

验收结论与本机运行证据记录在同目录 `validation.md`。本规格不把尚未运行或未取证的项目记作通过。
