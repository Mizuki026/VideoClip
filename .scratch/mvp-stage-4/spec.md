本窗口是第 4 窗口“正式 LLM 总结与引用发布”。第 3 窗口已经提供同一 task 下的安全恢复 attempt、绑定 task/attempt 的消息、严格检查点复用、删除和清理；第 2 窗口授权样片仍有 13/13 片转写，task 为 `awaiting_summary`，原执行已确认停止。它尚不是分析成功。产品决定继续不限制上传文件字节数和业务数据目录运行期 5 GiB 总量；保留媒体时长、E 盘持久化、单分析执行、有界模型请求及 Docker 新增占用 7 GiB 预算。

本窗口目标：

让拥有完整、已持久化转写的分析 task 经过真实免费 LLM 生成章节与知识要点，服务端严格校验并生成可溯源原文引用和视频时间区间，再以一次受执行资格约束的事务发布结果及 `succeeded`；校验或发布失败时不交付半成品，并可在确认停止后手动恢复而不重转写成功片段。

范围：

1. 先确定可验证的总结接力机制：现有转写 attempt 已领取一次并停止，不能靠重投旧消息让它重新执行。为已经存在的 `awaiting_summary` task 提供一次明确、幂等、可审计的续接入口或待总结投递路径；新提交任务转写完后也应能进入同一正式总结流程，无需伪造旧 attempt 的领取状态。继续使用同一 task、不可变 attempt 身份、每 attempt 投递事实、全局单执行占位与停止确认。任何消息重放、重复点击、API/Worker 重启都不得并发调用 LLM、产生第二份已发布结果或把旧执行者写回当前结果。恢复/续接与删除使用同一视频行锁；删除生效后不得继续请求模型或发布结果。
2. 审核 Stage 2/3 已保存的 `summary` 冻结快照：它已有供应商、模型、提示词版本、结构版本、上下文和输出 token 上限，但未必包含提示词内容摘要、temperature、thinking 模式及完整 LLM 请求期限。为新 task 保存足够重放的不可变配置和版本化模板；为既有 `awaiting_summary` task 建立明确的兼容校验或迁移规则，能从固定版本契约证明的参数才可补齐，无法证明时报告稳定不兼容原因。不得把运行时新默认值静默当作旧任务快照，也不得把密钥写入数据库。检查当前账户免费模型的可用性；如发生费用或额度不确定，不静默切换到付费模型或截断完整转写。
3. 在业务总结模块实现结构、引用和时间规则，并以受控 LLM 适配器调用真实接口。沿用已验证的 `stage0-summary-v4` 方向：LLM 从完整、按片序排列的转写中选择支撑章节/知识点的 `segment_id`，不直接提供 quote 或时间；服务端从对应已成功片段的原文确定性提取至多 48 字符连续引文。可复用探针经过验证的规则与测试思路，但不能让正式 Worker 依赖探针运行脚本或将其报告格式当作业务表。按冻结模板、模型参数、转写内容、修复反馈及结构版本形成带版本的 LLM 请求指纹；记录请求次数、耗时、usage、finish_reason、供应商追踪编号和有界错误，不把密钥、完整提示词、转写全文或原始响应写入普通日志。
4. 仅在当前 task/attempt 的预期清单非空、全部片段 `succeeded` 且源/清单/转写指纹一致时组装完整上下文；请求前校验实际上下文与冻结输出预留，超限给明确错误，不悄悄省略片段。LLM 请求设置连接、读取、写入和总期限，响应体/诊断字节及输出 token 上限；鉴权、限流、网络、超时、模型不兼容、JSON 无效及截断分别映射稳定错误。无业务自动网络重试；首次结构或引用校验失败可带有界反馈最多修复 2 次，总结请求总数最多 3。`finish_reason=length` 不是成功；耗尽后记录失败并保留转写供手动恢复。
5. 严格校验章节与知识要点的数量、非空字段、类型、未知字段及引用编号；引用只能指向本次 task 当前有效 attempt 的完整成功片段。按固定版本的 NFKC、大小写折叠和空白规则检查 quote 为对应原文的连续子串，不允许模型虚构、改写或从其他视频借用；章节/知识点及引用时间只能由持久化的视频区间推导，必须是有限数且满足 `0 <= start < end <= video_duration`。对于当前已验证的单片段证据契约，不为未来跨片段格式放松校验；若需要调整契约，先更新冻结结构版本和相关测试。引用真实性与定位通过不等于结论语义正确，真实样本需人工浏览若干章节点确认没有明显错位。
6. 为合法总结建立持久化结构、唯一发布约束和所属用户只读 `/videos/{id}/summary` 接口；未完成、失败、删除中和跨账号访问返回明确且不泄露的状态。结果写入、task/attempt 转 `succeeded`、所用转写/提示词/模型版本与摘要、请求审计及清理意图必须在同一短事务中再次核验当前视频、task、attempt、执行标识、有效检查点和未删除条件；不能在外部模型调用期间持有长事务。旧执行、重复消息、数据库提交失败或删除竞态不能发布半成品。模型已返回但发布事务失败时不宣称成功，也不保证供应商侧恰好一次调用。
7. 总结失败、超时或 Worker 中断后的手动恢复沿用第 3 窗口停止确认和父子 attempt 规则，复用完整成功转写并直接重试总结，不再调用 ASR；重新构建所需清单/来源证明，但不要仅为总结重复提取音频。结果发布与临时目录清理状态独立：合法结果即使清理失败仍可读取，单独清理重试只碰文件，不调用 LLM/ASR。已删除视频及其总结按现有可重入删除流程清除，删除中只暴露所有者的删除进度。同步更新状态枚举、迁移、查询响应和所有受影响调用方，不改 Stage 1/2/3 已建立的鉴权、视频、转写及恢复 API 语义。
8. 在 .scratch/mvp-stage-4/validation.md 保存实现路径、迁移与服务命令、真实模型名和提示词版本、调用次数与耗时、引用校验计数、故障注入、停止确认、数据保护、Docker 占用及明确限制；完成有意义阶段后更新现有产品和技术进度。真实验收优先复用第 2 窗口已有 13/13 授权转写以避免重复 ASR；若旧冻结配置确实无法安全续接，明确记录阻塞原因，用隔离的授权样本验证完整新链路，不篡改既有记录以求通过。第 0 窗口私密报告可作为受限诊断证据，但不得复制内容到 Git。

非目标：

- 不实现 React 注册/列表/详情页面、引用点击播放、同源 `/api` 代理或公开部署；当前后端 `/videos` 路由继续兼容，页面交互留给下一窗口。
- 不实现自动恢复停止未确认的 Worker、自动重投 Outbox、无限重试、付费模型回退、跨账号内容共享，也不以合成或假 LLM 输出冒充真实总结验收。
- 不扩展视频编码/时间轴支持范围，不恢复 1 GiB 上传字节上限、5 GiB 业务目录硬限额或容量水位拒绝测试；不清理其他 Docker 项目及历史业务数据。

验收：

1. 单元与隔离集成测试覆盖完整/缺失/重复/错序转写清单、冻结配置兼容、上下文预算、超限响应、错误分类、请求指纹、三次请求上限、首次截断后有限修复、未知字段、错误片段、伪造 quote、无效时间、NaN/Infinity、来源不一致和空引用。任一非法输出都不能出现 `succeeded` 或可读半成品；合法结果的章节、知识点、引文和视频区间可稳定重读。
2. 真实 PostgreSQL + Redis/Celery 测试证明已停止的 `awaiting_summary` 可恰好创建一个有效续接并完成总结，新转写任务也能进入同一路径；重复投递、并发续接、Worker 崩溃、LLM 返回后数据库失败及与删除竞争时，无旧 attempt 发布、无第二个结果、无 ASR 重调。总结失败后取得停止确认再手动恢复，沿用冻结配置及完整转写，仅追加必要的 LLM 请求；若清理失败，合法总结仍可读取，再次清理不会增加模型调用。
3. 使用经授权的真实课程转写和已确认可免费调用的 LLM，通过实际 API → Worker → LLM → 校验 → PostgreSQL → 所属用户总结接口跑通至少一条闭环；优先验证原第 2 窗口 13/13 `awaiting_summary` task。记录实际模型、提示词/结构版本、请求次数、耗时、finish_reason、章节/知识点/引用数量及时间/原文匹配结果，但不在验收记录复制原文、引文或密钥。重启 API/Worker 后结果仍可读，原视频和转写仍保留。免费接口不可用时记录具体阻塞及隔离验证，不能声称真实闭环通过。
4. 先跑直接相关测试，再跑完整适用后端与第 0 窗口回归、Ruff 格式/lint、Mypy、依赖、Alembic 和 Compose 校验；若构建镜像，核对本项目 Docker 新增镜像、缓存、可写层与日志预算不超过 7 GiB。核验 Stage 1/2 健康与既有业务任务、检查点和删除/恢复行为未被破坏，报告实际运行命令与结果。
5. 交付数据库迁移、业务模型/校验器/适配器、API/Worker 接力、测试、.scratch/mvp-stage-4/validation.md、必要的方案进度更新及逻辑提交哈希。只有真实结果发布和上述验证通过，才称“第 4 窗口正式总结与引用发布阶段通过”；MVP 页面闭环仍待下一窗口。

开始修改前及每次提交前检查工作区与暂存区，保留用户已有改动。先阅读现有实现并运行直接相关测试，再逐步实现、验证并按可独立验收的逻辑单元使用 Conventional Commits（英文类型、简洁中文描述）提交。不要提前实现前端窗口范围；若现有冻结快照或单次领取契约阻碍安全续接，先以测试和数据库事实确定最小迁移/接力方案，再动状态机，不能通过强制重领旧 attempt 或直接更新 `succeeded` 绕过执行资格。
