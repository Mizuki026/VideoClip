本窗口目标：

通过可重复运行的独立探针，验证免费模型、媒体时间映射、本机持久化和 Docker 增量预算，并形成是否允许进入第 1 窗口的证据。本规格中原 5 GiB 业务数据硬限制及容量准入相关要求，已由用户在 2026-09-29 明确暂时取消，按下文覆盖执行。

范围：

1. 检查工作区、现有实现、本机工具、Docker 环境及磁盘占用基线；只准备本项目的最小探针运行环境、必要依赖、版本锁定、配置示例与测试。探针代码集中在 probes/ 及对应测试目录，不创建正式业务模块；记录实际验证过的版本，未验证的兼容性明确标为待验证。
2. 核对硅基流动官方资料和当前账号可用的免费 ASR、LLM。用用户授权的 `video/` 目录样本，验证有效时长大于 0 且不超过 20 分钟的媒体，跑通 ffprobe → FFmpeg 提取音频与约 30 秒切片 → 顺序真实 ASR → 真实 LLM 总结 → 结构、原文引用和时间校验。**不设上传视频字节数上限。** 模型和请求参数通过配置提供。探针按本次完整片段清单校验结果，不实现正式数据库检查点与任务发布逻辑。
3. 记录模型、音频规格、提示词版本、请求耗时、响应结构、实际费用依据、限流及技术术语表现；核验 20 分钟课程规模的完整转写、提示词及预期输出上下文预算，说明估算方法和实测依据。小样本成功不能替代规模预算验证，不截断全文绕过限制，不静默切换付费模型。
4. 验证原视频播放器时间轴与提取音频时间轴的关系，包括音轨起始偏移样本。保存探针片段的音频/视频区间与映射依据，明确可播放且可可靠映射的封装、编码及时间轴白名单；不支持的样本明确拒绝。允许使用最小播放核验工具，不开发正式前端页面。
5. 使用本项目隔离的探针环境验证 PostgreSQL、Redis 的 E 盘持久化、重启与备份恢复；允许建立探针专用表和数据。继续核验 E 盘路径绑定和数据持久化。依据用户后续决定，暂不实施业务数据目录运行期 5 GiB 硬限制、容量准入水位、容量预留、按容量拒绝，以及对应写满 / 临界水位测试；不确定 I、M 或 L-I-M 准入水位，也不以监测或告警替代硬限制。
6. 为媒体子进程及网络请求配置有限总期限、停止宽限期、响应体及诊断大小上限。真实调用记录实际观察到的错误；未自然出现的鉴权、限流、慢响应及挂起场景通过受控模拟验证，明确区分实测与模拟。LLM 输出修复最多 2 次，总计最多 3 次总结请求，不增加自动业务重试。
7. 记录 Docker 新增占用的预计及实测值，覆盖镜像、构建缓存、容器可写层和日志，并与原有基线比较。授权原始样本位于仓库根目录 `video/` 并排除出 Git；音频、探针输出、数据库数据和临时业务文件放入 E:\VideoClip\data 下本项目专属、受限制的隔离目录并排除出 Git；密钥只从本地私密配置读取，不打印、不提交。
8. 保存可复现命令、结果摘要、证据位置和关卡结论至 .scratch/mvp-stage-0/validation.md；完成有意义的验证后更新现有技术方案的当前进度、已验证参数和下一步。已通过、失败、因缺少条件未执行分别记录。

非目标：

- 不实现正式账户与鉴权、上传 API、视频管理 API、业务数据库模型及迁移、任务状态机、attempt、投递器、Celery 业务 Worker、人工恢复和检查点持久化。
- 不实现正式 ASR/LLM 适配层、业务摘要发布、容量预留交接或删除/清理生命周期；允许探针所需的最小调用、校验、预算计算与测试代码。
- 不开发 React 正式页面、断点续传、自动 Outbox 发布器、Scheduler、自动故障接管、自动业务重试、MinIO、整段视频转码或线上部署。
- 不迁移全局 Docker 数据、清理其他项目、修改其他项目配置或扩大硬件/存储预算。

验收：

1. 真实模型闭环：提供探针启动命令、必要配置名和合法样本输入方式，实际运行 0 < 时长 ≤20 分钟真实调用链路（本次可用样本不要求 1–3 分钟）。片段清单完整，章节及知识要点结构合法，引用指向本次已有片段，原文按明确规范化规则连续匹配，时间区间由片段推导且有效；非法输出明确失败。测试结果注明实际模型、提示词版本、耗时及费用依据，模拟响应不能代替真实模型验收。
2. 规模与时间轴：提交 20 分钟课程上下文预算的计算及验证依据；普通样本和带音轨偏移样本经实际播放器回放核验语音内容对应，或对未支持的时间轴明确拒绝。只证明数值范围合法不能通过对齐验收。
3. 持久化：在本项目隔离环境写入 PostgreSQL、Redis 探针数据，重启对应容器后验证仍可读取，并执行备份恢复核验。检查数据实际落在 E 盘受限目录内，不用默认 Docker 卷绕过路径要求。
4. 业务数据容量限制：**用户已暂时取消本项验收**。不配置或实施运行期 5 GiB 总量硬限制、容量准入水位、容量预留和基于容量的上传 / 分析 / 重试拒绝；不运行写满、拒写及临界水位测试。文件系统常规写入错误仍须安全失败，但不作为容量准入保证。
5. 有界执行：直接相关测试验证有限总期限能终止持续慢响应和挂起的媒体进程，确认所属子进程已退出；校验非法引用、响应超限和总结修复次数上限。先运行相关测试，再运行本窗口适用的配置解析、lint、类型检查及完整探针测试；仅报告实际执行过的命令和结果。
6. Docker 预算：记录 Docker 基线和完整真实样本探针处理后的占用，覆盖镜像、构建缓存、容器可写层和日志，证明本项目新增占用不超过 7 GiB，并确认原有 Docker 项目未被修改；Stage 0 独立媒体探针运行于宿主机，本窗口未构建正式业务镜像。5 GiB 业务目录写满 / 拒写压力测试不执行。
7. 交接：所有仍在范围内的关卡均有证据通过时，才结论为“允许进入第 1 窗口”。容量限制关卡按用户决定列为已取消，不记作通过。交付探针、测试、最小环境配置、验证记录、已验证模型/媒体白名单/期限/预算参数、复现与安全清理步骤，以及逻辑提交的 commit 哈希；此结论不代表完整 MVP 已通过验收。
