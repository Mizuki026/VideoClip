# 课程视频转写与可追溯总结平台：MVP 产品设计

> 状态：MVP 范围已确认，当前处于设计阶段。
> 更新日期：2026-09-29。架构契约已补充，模型、环境及业务行为仍待实施验证。

## 1. 产品定位

面向中文技术课程学习场景，将视频中的语音讲解转为文字、章节大纲和知识要点，并提供原文引用与时间区间，方便用户回到视频核实内容。

产品用于个人本地使用，以及 Python 后端开发 / AI 应用开发实习求职的技术展示。MVP 重点展示真实模型接入、可恢复的转写流程、结构化输出和证据定位能力。分析范围为语音讲解，不包含画面、屏幕代码或图表理解。

参考 [DOVideo-AI](https://github.com/Xiaoc7r/DOVideo-AI) 的视频任务与时序文本处理思路，采用 Python 独立实现。

## 2. 核心使用流程

注册 / 登录 → 上传课程视频 → 查看异步处理进度 → 阅读转写和总结 → 点击引用回看对应片段 → 删除记录释放空间。

处理流程：提取音频 → 按约 30 秒切片 → 逐片转写并保存 → 全部片段完成后生成总结 → 自动校验结构与引用 → 展示结果。

## 3. MVP 主要功能

| 功能 | MVP 范围 |
| --- | --- |
| 基础鉴权 | 用户名密码注册、登录、退出；用户只能访问自己的视频、任务和结果。 |
| 视频上传 | 普通流式上传到 E 盘，展示上传进度；服务端校验文件大小、视频时长、媒体有效性和音轨。 |
| 异步任务 | 提交分析后返回任务信息，展示投递情况、处理阶段、已转写片段数和失败原因；同时执行一个分析任务，投递异常可手动恢复。 |
| 音频转写 | FFmpeg 提取并切分音频，调用真实 ASR；保存每个片段的编号、文本和时间区间。 |
| AI 总结 | 生成章节大纲、知识要点、原文引用和时间区间；自动校验输出结构、引用片段、原文匹配及时间范围，允许有限次数的输出修复。 |
| 视频详情 | 同页展示播放器、转写和总结；点击引用，从对应片段起点回放。 |
| 手动恢复与清理 | 重试沿用原处理配置并复用已持久化成功的转写，补跑失败或未完成片段；清理可以单独重试，支持整条记录及关联文件删除。 |

缺失片段尚未补齐时，不交付成功的全课总结。原视频保留至用户主动删除；MVP 删除整条记录时，同时删除关联转写、任务和总结。

成功片段指成功检查点已经提交数据库的片段。模型已经返回但检查点尚未提交时发生中断，恢复后可能再次请求该片段，不承诺外部模型调用恰好一次。重试使用原任务冻结的切片、ASR 和总结配置；原配置不再可用或当前程序无法兼容时，显示明确原因，不静默切换模型或混用检查点。

投递失败、投递结果不确定或排队长时间未开始时，页面提供原因与手动恢复入口；在确认原尝试尚未开始且原子失效后，可恢复投递，无须重启整个服务。曾经开始执行的尝试必须取得执行者及媒体子进程的停止确认，才能创建新的尝试或清理其文件。无法确认时提示用户停止本项目 Worker、按恢复步骤确认退出后再继续；心跳超时和任务失败状态都不能单独作为停止证明。本版不自动接管或重跑中断任务。

总结校验通过并保存后即可阅读。临时文件清理状态单独展示；清理失败保留正确的分析结果和实际占用，用户可再次清理，清理重试不会重新调用模型。删除记录后立即禁止新的内容访问和分析，保留所属用户可见的删除进度；停止执行者、文件回收及关联数据清理全部完成后才显示删除完成。

模型优先使用硅基流动的免费 ASR 和免费 LLM，具体模型需先验证接口能力。每次任务记录使用的模型和提示词版本。免费接口限流或不可用时，展示明确原因，允许条件恢复后手动重试。

## 4. 页面结构

- **注册 / 登录页**：完成账号创建和登录。
- **视频列表页**：上传视频，查看视频和任务状态，进入详情，删除记录并查看删除进度。
- **视频详情页**：查看投递、处理及清理状态和错误，执行手动恢复或再次清理，阅读转写及总结，点击时间区间回看视频。

## 5. 规模与资源约束

| 项目 | 约束 |
| --- | --- |
| 单个视频 | 最长 20 分钟，最大 1 GiB。 |
| 分析并发 | 同时执行一个视频分析任务。 |
| 业务数据 | 总占用硬上限 5 GiB，包含原视频、上传临时文件、处理文件、数据库（含 WAL）和队列持久化数据；上传前预留上传 / 处理空间，并保留基础设施增长和失败记录、删除、清理所需余量。 |
| 数据位置 | 视频、数据库持久化目录和临时业务文件放在 `E:\VideoClip` 下的独立数据目录。 |
| 运行方式 | 本地个人使用与演示，不部署上线；存储预算为零。 |
| 时间定位 | 约 30 秒切片区间，统一映射到原视频播放器时间轴；提供片段级定位，不承诺句级或词级精度。 |

新增上传、分析和重试在准入水位不足时停止，提示清理或具体资源原因；准入水位必须低于 5 GiB 硬上限，不能等磁盘写满后才拒绝。上传预留随视频及任务转移，失败或完成后仅释放已经不再需要的预留；再次分析或重试需重新取得处理预算。读取已有结果及删除、清理入口继续可用，文件释放量以实际占用为准，删除数据库记录不保证立即缩小数据库文件。

第 1 阶段必须验证覆盖全部业务目录的硬限制机制、计量口径及保留余量，单靠定时统计和告警不能证明 5 GiB 上限成立。环境无法实现时，先记录阻塞并提出调整方案，取得明确的产品范围决定后再推进，不将硬上限静默降为监测目标。

上传时说明已验证可播放、可映射时间轴的封装与编码范围；对无法可靠映射的媒体明确拒绝。本版不进行整段视频自动转码。MVP 采用普通上传，上传中断后需重新上传文件。

Docker 新增占用单独评估，计入镜像、构建缓存、容器可写层和日志。预计及实测新增占用不超过 7 GiB 时沿用现有 Docker 环境；超出时先提出调整或迁移方案。全局迁移必须安排现有项目基线检查、备份、回滚和运行验证，保护本机已有 Docker 项目。

## 6. MVP 验收标准

- 至少一段真实课程样本完成上传、真实 ASR、真实 LLM 总结及视频回看。
- 输出结构合法，引用片段存在，原文引用可匹配，时间范围有效；非法输出不会被标记为成功。
- 点击引用可以跳转到对应视频时间区间；带音轨起始偏移的样本正确映射或被明确拒绝，区间合法但内容错位不能通过。
- 跨账号访问其他用户资源被拒绝。
- 转写失败后手动重试，已持久化成功的片段不会重新转写；修改默认配置或重启服务后仍沿用冻结配置，失败原因和进度可见。
- 数据库提交后尚未投递、投递已成功但确认丢失、重复及迟到消息得到验证；遗留排队任务有手动恢复路径，过期尝试不能回写结果。
- 模型请求或媒体进程挂起时，在配置的总期限到期后停止新增工作并触发有界停止流程；旧执行者退出未确认时阻止新尝试和文件清理。
- 大小、时长、单分析并发、5 GiB 硬上限及临界水位下上传、重试、记录删除与临时文件清理得到验证。
- 分析成功但清理失败时，结果仍可阅读，占用及清理错误可见；再次清理不调用模型，删除未完成不能显示完成。

验收以可复现的工程行为为依据。允许总结遗漏重要知识点，不加入人工标注，不将知识点覆盖或语义准确性作为验收门槛。原文引用校验用于验证引用来源与定位，不证明结论在语义上正确。

## 7. 技术方向与后续迭代

技术方向：FastAPI、Pydantic、SQLAlchemy、PostgreSQL、Redis、Celery、FFmpeg、React、TypeScript 和 Docker Compose。任务状态与转写检查点持久化，业务文件通过后端鉴权接口访问。

实施起点是用一段 1–3 分钟视频验证免费 ASR、免费 LLM 和引用输出能真实跑通，同时确认时间轴映射、E 盘持久化、容量硬限制与 Docker 占用，再完成上述 MVP 闭环。小样本用于能力验证，不能替代 20 分钟规模和故障边界验收。整体首版按 6 周、每周 12–15 小时规划，功能开发同步进行必要的自动验证；环境或模型门槛未通过时，先处理阻塞再扩大范围。

MVP 完成后补充：

- 约 8 MiB 分片上传、断点续传和幂等合并。
- Worker 崩溃后的自动恢复、限流后的自动等待与重试。
- 单独删除原视频并保留文字笔记，明确显示原视频缺失并关闭回看入口。
- 更完整的故障演示与执行记录。
