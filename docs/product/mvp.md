# 课程视频转写与可追溯总结平台：MVP 产品设计

> 状态：MVP 范围已确认，当前处于设计阶段。

## 1. 产品定位

面向中文技术课程学习场景，将视频中的语音讲解转为文字、章节大纲和知识要点，并提供原文引用与时间区间，方便用户回到视频核实内容。

产品用于个人本地使用，以及 Python 后端开发 / AI 应用开发实习求职的技术展示。MVP 重点展示真实模型接入、可恢复的转写流程、结构化输出和证据定位能力。分析范围为语音讲解，不包含画面、屏幕代码或图表理解。

参考 [DOVideo-AI](https://github.com/Xiaoc7r/DOVideo-AI) 的视频任务与时序文本处理思路，采用 Python 独立实现。

## 2. 核心使用流程

注册 / 登录 → 上传课程视频 → 查看异步处理进度 → 阅读转写和总结 → 点击引用回看对应片段 → 删除记录释放空间。

处理流程：提取音频 → 按约 30 秒切片 → 逐片转写并保存 → 全部片段完成后生成总结 → 自动校验结构与引用 → 展示结果。

## 3. MVP 主要功能

| 功能 | MVP 范围 |
| --- | --- |
| 基础鉴权 | 用户名密码注册、登录、退出；用户只能访问自己的视频、任务和结果。 |
| 视频上传 | 普通流式上传到 E 盘，展示上传进度；服务端校验文件大小、视频时长、媒体有效性和音轨。 |
| 异步任务 | 提交分析后返回任务信息，展示处理阶段、已转写片段数和失败原因；同时执行一个分析任务。 |
| 音频转写 | FFmpeg 提取并切分音频，调用真实 ASR；保存每个片段的编号、文本和时间区间。 |
| AI 总结 | 生成章节大纲、知识要点、原文引用和时间区间；自动校验输出结构、引用片段、原文匹配及时间范围，允许有限次数的输出修复。 |
| 视频详情 | 同页展示播放器、转写和总结；点击引用，从对应片段起点回放。 |
| 手动恢复与清理 | 重试时复用成功转写，补跑失败或未完成片段；支持整条记录及关联文件删除，及时清理临时文件。 |

缺失片段尚未补齐时，不交付成功的全课总结。原视频保留至用户主动删除；MVP 删除整条记录时，同时删除关联转写、任务和总结。

模型优先使用硅基流动的免费 ASR 和免费 LLM，具体模型需先验证接口能力。每次任务记录使用的模型和提示词版本。免费接口限流或不可用时，展示明确原因，允许条件恢复后手动重试。

## 4. 页面结构

- **注册 / 登录页**：完成账号创建和登录。
- **视频列表页**：上传视频，查看视频和任务状态，进入详情，删除记录。
- **视频详情页**：查看进度和错误，执行手动重试，阅读转写及总结，点击时间区间回看视频。

## 5. 规模与资源约束

| 项目 | 约束 |
| --- | --- |
| 单个视频 | 最长 20 分钟，最大 1 GiB。 |
| 分析并发 | 同时执行一个视频分析任务。 |
| 业务数据 | 总占用上限 5 GiB；上传及处理中间文件纳入容量控制，上传前预留上传 / 处理所需临时空间。 |
| 数据位置 | 视频、数据库持久化目录和临时业务文件放在 `E:\VideoClip` 下的独立数据目录。 |
| 运行方式 | 本地个人使用与演示，不部署上线；存储预算为零。 |
| 时间定位 | 约 30 秒切片区间，提供片段级定位，不承诺句级或词级精度。 |

达到容量上限时停止新上传并提示清理。MVP 采用普通上传，上传中断后需重新上传文件。

Docker 新增占用单独评估，计入镜像、构建缓存、容器可写层和日志。预计及实测新增占用不超过 7 GiB 时沿用现有 Docker 环境；超出时先提出调整或迁移方案。全局迁移必须安排现有项目基线检查、备份、回滚和运行验证，保护本机已有 Docker 项目。

## 6. MVP 验收标准

- 至少一段真实课程样本完成上传、真实 ASR、真实 LLM 总结及视频回看。
- 输出结构合法，引用片段存在，原文引用可匹配，时间范围有效；非法输出不会被标记为成功。
- 点击引用可以跳转到对应视频时间区间。
- 跨账号访问其他用户资源被拒绝。
- 转写失败后手动重试，已成功的片段不会重新转写；失败原因和进度可见。
- 大小、时长、并发与容量限制，以及记录删除和临时文件清理得到验证。

验收以可复现的工程行为为依据。允许总结遗漏重要知识点，不加入人工标注，不将知识点覆盖或语义准确性作为验收门槛。原文引用校验用于验证引用来源与定位，不证明结论在语义上正确。

## 7. 技术方向与后续迭代

技术方向：FastAPI、Pydantic、SQLAlchemy、PostgreSQL、Redis、Celery、FFmpeg、React、TypeScript 和 Docker Compose。任务状态与转写检查点持久化，业务文件通过后端鉴权接口访问。

实施起点是用一段 1–3 分钟视频验证免费 ASR、免费 LLM 和引用输出能真实跑通，再完成上述 MVP 闭环。整体首版按 6 周、每周 12–15 小时规划，功能开发同步进行必要的自动验证。

MVP 完成后补充：

- 约 8 MiB 分片上传、断点续传和幂等合并。
- Worker 崩溃后的自动恢复、限流后的自动等待与重试。
- 单独删除原视频并保留文字笔记，明确显示原视频缺失并关闭回看入口。
- 更完整的故障演示与执行记录。
