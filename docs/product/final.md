# 课迹：最终版产品设计

> 状态：最终目标、范围及架构审查中的关键取舍已确认；第 1 窗口分片上传、第 2 窗口浏览器续传与临时上传回收、第 3 窗口可信停止确认、第 4 窗口排队协调与投递补偿均已实施并验收。共享限流、执行失败后的受控自动恢复及媒体/笔记分离仍待后续窗口。MVP 已完成，历史范围见 [MVP 产品设计](mvp.md)。
> 更新日期：2026-10-03。

## 1. 目标与定位

课迹面向个人本地使用，将中文技术课程视频中的语音讲解整理为分段转写、章节和知识要点。每条总结引用可定位到原视频片段，方便用户核对。项目同时作为 Python 后端开发与 AI 应用开发实习求职的技术展示：演示者能够复现完整流程，并解释媒体处理、异步任务、模型调用、结果校验和故障恢复的设计取舍。

技术实现沿用 Python / FastAPI、PostgreSQL、Redis / Celery、FFmpeg、React / TypeScript 和 Docker Compose。展示重点是跨浏览器、后端、媒体工具和真实模型的完整链路，以及可观察、可恢复的数据处理过程。

分析对象是视频中的语音。产品不理解画面、屏幕代码或图表；引用与时间校验只能证明输出有可核对的来源，不能证明总结在语义上准确或覆盖课程全部重要概念。

## 2. 用户流程

注册 / 登录 → 上传课程视频，必要时从中断处续传 → 提交分析并查看进度 → 阅读转写和总结 → 点击引用回看对应片段 → 按需单独删除原视频并保留笔记，或删除整条记录。

后台流程为：校验媒体与时间轴 → 提取并切分音频 → 逐片调用真实 ASR 并保存检查点 → 在转写片段齐全后调用真实 LLM → 校验结构、原文引用和时间范围 → 发布唯一的可读总结。失败或中断时显示原因、恢复状态及用户可采取的操作。

## 3. 最终版功能范围

MVP 已提供账号隔离、普通流式上传、单任务异步分析、真实 ASR / LLM、分段检查点、引用回看、手动恢复、整条记录删除及临时文件清理。最终版在此基础上完成以下能力：

| 能力 | 最终版要求 |
| --- | --- |
| 大文件续传 | 分片上传并支持中断后续传；重复分片或重复完成请求不会生成重复视频。展示上传与续传进度，过期或放弃的临时分片可安全清理。具体分片大小在技术设计中确定。 |
| 受控自动恢复 | 对 Worker 崩溃、投递异常及模型限流提供有界的自动恢复或等待；复用已持久化且配置匹配的成功转写片段。仅在旧执行者已确认停止，或可原子证明任务从未开始时接管。排队任务在执行阻断解除后继续接受协调，不因一次消息被消费而永久失去执行机会。无法证明安全时阻断自动恢复，保留明确的人工处理入口。 |
| 视频与笔记分别管理 | 支持单独删除原视频，保留已合法持久化的转写、章节和知识要点。删除意图生效后取消所有未完成分析，关闭播放器及引用回看；页面区分删除处理中、清理失败和原视频已删除。继续支持删除整条记录及其关联数据。 |
| 可观察的执行过程 | 用户可看到上传、投递、转写、总结、等待、恢复和清理状态；失败显示稳定原因及下一步操作。演示材料能复现至少一个受控故障及恢复过程，不暴露凭据或课程原文。 |

沿用 MVP 的结果发布规则：缺少预期转写片段或引用校验失败时不发布成功总结；恢复时沿用任务冻结的模型、切片和提示词配置；旧尝试与迟到消息不能覆盖已发布结果。外部模型请求可能因检查点提交前中断而重复，不承诺恰好调用一次。

模型限流按实际共享额度的供应商、账户和模型协调冷却。同一受限模型的其他任务也等待，但不受影响的阶段可以继续，例如 LLM 冷却期间允许其他视频转写；等待任务在执行停止已确认后释放分析执行位，仍保持全部署单分析并发。

补投使用独立的有界策略。实际执行失败后的自动恢复最多 2 次/任务；扫描、重复操作和等待冷却本身不消耗该额度。总结请求每 task 最多 3 次，跨自动与人工尝试共享；自动恢复可以用完全部额度，不为人工恢复预留一次。请求启动前预留额度，失败或启动记录提交后中断也可能占用额度，不据此判断供应商是否实际收到请求或计费。额度耗尽后保留转写并显示明确原因，关闭无效的总结恢复入口，不能通过补投或恢复重置额度。

媒体删除以删除意图持久化为生效点：保留此前合法提交的笔记，取消排队、运行、限流等待及等待总结等所有未完成分析，拒绝之后的结果写回和发布；即使转写完整，也不在删除后补生成总结。清理失败时删除意图持续生效，笔记仍可读，媒体和分析保持关闭，仅允许重试清理，本版不提供撤销删除。媒体访问承诺阻断生效后的新请求，不承诺追回已打开响应或已经下发的内容。

## 4. 规模、资源与边界

| 项目 | 最终版约束 |
| --- | --- |
| 视频时长 | 有效时长大于 0 且不超过 20 分钟；媒体格式及时间轴必须能被可靠校验和映射。 |
| 上传字节数 | 不设置单个视频的业务字节硬上限。实际磁盘空间不足或文件写入失败时明确报错并安全清理，不把存储失败伪装成分析成功。 |
| 业务数据总量 | 不设置 5 GiB 或其他运行期硬上限，不以业务数据目录占用量作为上传、分析或重试的固定准入门槛；仍记录实际占用并提供删除、清理能力。 |
| 执行并发 | 本地部署同时执行一个分析任务，其余任务排队；自动恢复不得突破该约束。 |
| 数据位置 | 视频、数据库持久化数据和临时业务文件留在 `E:\VideoClip\data` 下的项目目录；授权样片留在 `video\`，不提交到 Git。 |
| 模型与费用 | 优先使用已验证可用的免费 ASR 和免费 LLM；不自动切换付费模型。验收时核对账户中的模型可用性与计费信息，不将本地配置的零费率当作账单回执。 |
| 运行方式 | 本地个人使用和演示，不计划公开部署；存储预算为零。Docker 新增占用预计及实测均不超过 7 GiB 时沿用现有环境；若确需调整或迁移全局数据，先评估、备份、设计回滚并验证本机其他项目。 |

产品不扩展到画面理解、屏幕文字识别、课程问答、句级或词级时间戳、通用视频转码、移动端及多人线上服务。最终验收不引入人工标注，也不以知识点覆盖率或总结语义准确率作为通过条件。

## 5. 完成标准与演示证据

1. 使用 `video\` 中新增的约 17 分钟授权中文技术课程作为最终版主要验收样本。先核验其实际时长和媒体适配性，再在真实浏览器中完成上传、真实 ASR、真实 LLM、结果持久化和引用回看；不能仅以旧的约 6 分钟 MVP 样本代替。20 分钟时长边界另行验证。
2. 在该样本上演示上传中断后的续传、重复请求的幂等行为，以及失败时临时文件的安全清理；不因样片的字节数设置新的产品硬上限。
3. 演示至少一次 Worker 中断及一次模型限流或等效可控故障：安全恢复后已提交转写片段得到复用，任务最终只发布一个合法总结；旧执行者停止未确认时系统拒绝接管与文件清理。隔离回归同时验证共享模型冷却、不受限阶段继续、阻断解除后排队任务继续执行，以及补投、自动恢复和总结请求额度的独立计数与耗尽行为。
4. 点击至少两处不同引用，播放器定位到有效片段并继续播放；删除原视频后笔记仍可读、回看入口不可用，生效后的新媒体请求被拒绝；删除整条记录后相关内容不可访问。隔离回归验证未完成任务被取消、迟到结果不能提交，以及清理失败后笔记可读、媒体仍被阻断且可重试清理。
5. 从仓库说明可在本机复现正常流程与故障流程。保留必要的测试、运行记录和资源占用证据，使演示者能解释适用范围、失败模式和设计取舍。验收记录区分已经实测的事实与尚未验证的能力。

验收只证明流程、数据归属、引用来源与时间定位、恢复安全性和可复现性；不据此宣称课程内容被完整理解。

## 6. 当前进度与实施顺序

MVP 最终验收已经通过，证据见[第六窗口验收记录](../../.scratch/mvp-stage-6/validation.md)：真实浏览器使用 368.6 秒授权样本完成 13 段转写、真实总结、人工恢复和引用回看。最终版第 0 窗口的约 17 分 41 秒样片基线也已在真实浏览器通过：36 段转写、真实总结、两处引用回看及 API/Worker 重启读回，详见[第 0 窗口验收记录](../../.scratch/final-stage-0/validation.md)。这只证明该样片和当前本机环境的基线链路；20 分钟真实模型处理及账户账单尚未验证。第 1 窗口分片上传、第 2 窗口浏览器断点续传与临时上传周期回收、第 3 窗口可信停止确认、第 4 窗口排队协调与投递补偿均有独立实现与验收记录。共享冷却、执行失败后的有界自动恢复及媒体删除的取消和访问边界仍待后续窗口；第 4 窗口不会自动接管已经开始执行的 attempt。

后续按以下顺序推进，每阶段完成后记录真实验证结果：

1. **第 0 窗口主流程完成，资源子项留有未验证项。** 新样片媒体属性、真实模型处理和业务目录/内存基线已记录；容器可写层处理中峰值未采样，E 盘空闲空间差额未归因。20 分钟真实模型处理及账户计费证据仍未验证。
2. **第 1 窗口后端与第 2 窗口浏览器续传/临时上传周期回收已完成。** 后端分片接口、真实浏览器重选续传及 Beat→Redis→维护 Worker 周期回收均已验收；普通上传兼容接口保留。第 2 窗口记录见[规格](../../.scratch/final-stage-2/spec.md)和[验收记录](../../.scratch/final-stage-2/validation.md)。
3. **第 3 窗口可信停止确认已完成。** 每个新 execution 绑定一次性 Worker 代次、容器、Linux boot ID 和受控 session；同容器监督器先确认整个 session 中本地执行者及后代退出，再通过统一事务登记证据。不能证明停止时保留全局占位，状态接口报告 `stop_unconfirmed` / `STOP_CONFIRMATION_REQUIRED`，禁止恢复和工作目录清理，人工入口只确认精确退出的 Worker 容器。真实进程和容器故障证据见[第 3 窗口验收记录](../../.scratch/final-stage-3/validation.md)。停止证明只覆盖已绑定的 Stage 2 Linux execution session；监督器/容器强停、身份缺失和证据不可验证时仍须人工处理。
4. **第 4 窗口排队协调与投递补偿已完成。** 不同视频可在分析位占用时持久排队，按入队时间和 task ID 公平领取；pending、unknown、已发送未领取和忙时 ACK 均由 PostgreSQL 维护的代次、检查时间及独立补投预算接续。真实 Beat→Redis→maintenance Worker→analysis Worker 链路确认忙时 ACK 后仍自动推进，全局最大未确认 execution 为 1。参数、历史行迁移和故障证据见[第 4 窗口记录](../../.scratch/final-stage-4/validation.md)。该窗口不自动恢复已经开始执行的失败 attempt。
5. 实现共享模型冷却和执行失败后的有界自动恢复；沿用停止确认与独立预算门禁。
6. 实现原视频单独删除与笔记保留，完成最终浏览器验收、复现文档和求职展示材料。

本文定义最终版目标；具体接口、状态转换、迁移和测试方案在各实施阶段设计，不以本文件替代技术方案。
