# 课迹：最终版产品设计

> 状态：最终目标与范围已确认，功能待实施和验收。MVP 已完成，历史范围见 [MVP 产品设计](mvp.md)。
> 更新日期：2026-10-03。

## 1. 目标与定位

课迹面向个人本地使用，将中文技术课程视频中的语音讲解整理为分段转写、章节和知识要点。每条总结引用可定位到原视频片段，方便用户核对。项目同时作为 Python 后端开发与 AI 应用开发实习求职的技术展示：演示者能够复现完整流程，并解释媒体处理、异步任务、模型调用、结果校验和故障恢复的设计取舍。

技术实现沿用 Python / FastAPI、PostgreSQL、Redis / Celery、FFmpeg、React / TypeScript 和 Docker Compose。展示重点是跨浏览器、后端、媒体工具和真实模型的完整链路，以及可观察、可恢复的数据处理过程。

分析对象是视频中的语音。产品不理解画面、屏幕代码或图表；引用与时间校验只能证明输出有可核对的来源，不能证明总结在语义上准确或覆盖课程全部重要概念。

## 2. 用户流程

注册 / 登录 → 上传课程视频，必要时从中断处续传 → 提交分析并查看进度 → 阅读转写和总结 → 点击引用回看对应片段 → 按需单独删除原视频并保留笔记，或删除整条记录。

后台流程为：校验媒体与时间轴 → 提取并切分音频 → 逐片调用真实 ASR 并保存检查点 → 在转写片段齐全后调用真实 LLM → 校验结构、原文引用和时间范围 → 发布唯一的可读总结。失败或中断时显示原因、恢复状态及用户可采取的操作。

## 3. 最终版功能范围

MVP 已提供账号隔离、普通流式上传、单任务异步分析、真实 ASR / LLM、分段检查点、引用回看、手动恢复、整条记录删除及临时文件清理。最终版在此基础上完成以下能力：

| 能力 | 最终版要求 |
| --- | --- |
| 大文件续传 | 分片上传并支持中断后续传；重复分片或重复完成请求不会生成重复视频。展示上传与续传进度，过期或放弃的临时分片可安全清理。具体分片大小在技术设计中确定。 |
| 受控自动恢复 | 对 Worker 崩溃、投递异常及模型限流提供有界的自动恢复或等待；复用已持久化且配置匹配的成功转写片段。仅在旧执行者已确认停止，或可原子证明任务从未开始时接管。无法证明安全时阻断自动恢复，保留明确的人工处理入口。 |
| 视频与笔记分别管理 | 支持单独删除原视频，保留转写、章节和知识要点；页面明确显示原视频已删除，关闭播放器及引用回看。继续支持删除整条记录及其关联数据。 |
| 可观察的执行过程 | 用户可看到上传、投递、转写、总结、等待、恢复和清理状态；失败显示稳定原因及下一步操作。演示材料能复现至少一个受控故障及恢复过程，不暴露凭据或课程原文。 |

沿用 MVP 的结果发布规则：缺少预期转写片段或引用校验失败时不发布成功总结；恢复时沿用任务冻结的模型、切片和提示词配置；旧尝试与迟到消息不能覆盖已发布结果。外部模型请求可能因检查点提交前中断而重复，不承诺恰好调用一次。

## 4. 规模、资源与边界

| 项目 | 最终版约束 |
| --- | --- |
| 视频时长 | 有效时长大于 0 且不超过 20 分钟；媒体格式及时间轴必须能被可靠校验和映射。 |
| 上传字节数 | 不设置单个视频的业务字节硬上限。实际磁盘空间不足或文件写入失败时明确报错并安全清理，不把存储失败伪装成分析成功。 |
| 业务数据总量 | 不设置 5 GiB 或其他运行期硬上限，不以业务数据目录占用量作为上传、分析或重试的固定准入门槛；仍记录实际占用并提供删除、清理能力。 |
| 执行并发 | 本地部署同时执行一个分析任务，其余任务排队；自动恢复不得突破该约束。 |
| 数据位置 | 视频、数据库持久化数据和临时业务文件留在 `E:\VideoClip\data` 下的项目目录；授权样片留在 `video\`，不提交到 Git。 |
| 模型与费用 | 优先使用已验证可用的免费 ASR 和免费 LLM；不自动切换付费模型。验收时核对账户中的模型可用性与计费信息，不将本地配置的零费率当作账单回执。 |
| 运行方式 | 本地个人使用和演示，不计划公开部署；存储预算为零。Docker 新增占用预计及实测均不超过 7 GiB 时沿用现有环境；若确需调整或迁移全局数据，先评估、备份、设计回滚并验证本机其他项目。 |

产品不扩展到画面理解、屏幕文字识别、课程问答、句级或词级时间戳、通用视频转码、移动端及多人线上服务。最终验收不引入人工标注，也不以知识点覆盖率或总结语义准确率作为通过条件。

## 5. 完成标准与演示证据

1. 使用 `video\` 中新增的约 17 分钟授权中文技术课程作为最终版主要验收样本。先核验其实际时长和媒体适配性，再在真实浏览器中完成上传、真实 ASR、真实 LLM、结果持久化和引用回看；不能仅以旧的约 6 分钟 MVP 样本代替。20 分钟时长边界另行验证。
2. 在该样本上演示上传中断后的续传、重复请求的幂等行为，以及失败时临时文件的安全清理；不因样片的字节数设置新的产品硬上限。
3. 演示至少一次 Worker 中断及一次模型限流或等效可控故障：安全恢复后已提交转写片段得到复用，任务最终只发布一个合法总结；旧执行者停止未确认时系统拒绝接管与文件清理。
4. 点击至少两处不同引用，播放器定位到有效片段并继续播放；删除原视频后笔记仍可读、回看入口不可用；删除整条记录后相关内容不可访问。
5. 从仓库说明可在本机复现正常流程与故障流程。保留必要的测试、运行记录和资源占用证据，使演示者能解释适用范围、失败模式和设计取舍。验收记录区分已经实测的事实与尚未验证的能力。

验收只证明流程、数据归属、引用来源与时间定位、恢复安全性和可复现性；不据此宣称课程内容被完整理解。

## 6. 当前进度与实施顺序

MVP 最终验收已经通过，证据见[第六窗口验收记录](../../.scratch/mvp-stage-6/validation.md)：真实浏览器使用 368.6 秒授权样本完成 13 段转写、真实总结、人工恢复和引用回看。新增约 17 分钟授权样片尚未在本项目中完成最终版验收，最终版增量功能也不得按 MVP 已完成项表述。

后续按以下顺序推进，每阶段完成后记录真实验证结果：

1. 核验新样片媒体属性与本机可用空间，建立长视频真实模型处理和资源占用基线。
2. 实现并验证分片续传与临时分片回收。
3. 实现并验证受控自动恢复、限流等待及故障演示。
4. 实现原视频单独删除与笔记保留，完成最终浏览器验收、复现文档和求职展示材料。

本文定义最终版目标；具体接口、状态转换、迁移和测试方案在各实施阶段设计，不以本文件替代技术方案。
